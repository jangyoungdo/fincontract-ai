# 실험 운영 가이드

## 목적

FinContract AI의 개발 작업을 측정 가능한 버티컬 AI 실험으로 운영합니다. 새로운 에이전트나 모델은 기술적 흥미가 아니라 기존 기준선의 명확한 실패를 해결할 때 추가합니다.

## 실험 단위

운영 API와 화면에는 A/D 실험군 선택을 노출하지 않습니다. 제품은 `19개 규칙 + 로컬 의미 후보 + 선택적 OpenAI 문맥 후보 + 근거·설명 보강`의 단일 `full_pipeline`을 실행합니다. 규칙만 실행하는 `rules-only`는 성능 회귀를 측정하기 위한 내부 평가 기준선이며 운영 기능이 아닙니다. 외부 문맥 검토·설명 보강 실패나 호출 예산 소진은 규칙 탐지를 변경할 수 없습니다.

하나의 실험은 하나의 질문만 다룹니다. 예시는 다음과 같습니다.

- RAG가 근거 없는 법적 참조를 줄이는가?
- 검증 에이전트가 잘못된 evidence ID를 차단하는가?
- 계획 에이전트가 긴 계약서의 누락률을 낮추는가?
- Hybrid Search가 vector-only 검색보다 인용 적합도를 높이는가?

가능하면 실험 하나를 GitHub Issue 하나, 브랜치 하나, worktree 하나와 대응시킵니다.

## 실행 절차

1. 실험 전 가설, 기준선, 변경 요소, 데이터 분할, 성공 기준을 기록합니다.
2. 비교군 사이에는 검증하려는 변수 하나만 변경합니다.
3. 모델명, 모델 버전, prompt 버전, 규칙 버전, corpus manifest, 코드 commit을 고정합니다.
4. 자동 평가를 실행한 뒤 사람이 오류 표본을 검토합니다.
5. 비용·지연·실패율을 품질 지표와 함께 기록합니다.
6. 결과를 `채택`, `보류`, `기각` 중 하나로 결정하고 이유를 남깁니다.

## 평가 데이터 원칙

- 검색·규칙 작성에 사용한 문서와 최종 평가 문서를 분리합니다.
- 문서 출처, 라이선스, 중복 제거 기준과 split을 manifest로 관리합니다.
- 개인정보 또는 내부 문서는 기본 평가셋에 커밋하지 않습니다.
- 전문가 의견이 불일치하면 억지로 하나의 정답을 만들지 않고 `needs_review` 또는 복수 라벨로 기록합니다.
- 모델 응답 원문에는 민감정보가 포함될 수 있으므로 공개 저장소에 그대로 첨부하지 않습니다.

## 평가 기준선 운영

동일한 정제·분리 결과에 대해 `rules-only`와 `full`을 평가합니다. full의 `findings[]`는 rules-only와 완전히 같아야 하며, 성능 증분은 별도 `candidate_findings[]`에서만 측정합니다. 후보 임계값은 공개 합성 개발셋에서 정밀도 75% 제약 아래 F1을 최대로 하는 값으로 정하고 비공개 승인셋은 최종 평가에만 사용합니다.

규칙셋 0.4.0의 고정 E5 리비전에서 선택된 운영 임계값은 `0.90`, 안전 예문 대비 최소 간격은 `0.04`입니다. 재보정할 수 없을 때만 `0.72`를 fallback으로 사용하며, 비공개 MVP 문서 점수로 이 값을 조정하지 않습니다.

## 병합 조건

- 실험 코드와 함께 재현 명령 또는 자동화 테스트가 있어야 합니다.
- 결과가 불리해도 삭제하지 않고 결정 근거를 남깁니다.
- 개인정보·법률 경계를 위반한 실험은 성능과 무관하게 채택하지 않습니다.
- 새 에이전트는 단일 에이전트 대비 개선값과 추가 비용을 함께 제시해야 합니다.
